# ADR-0031：允许独立测试与验证脚本

- 状态：Accepted
- 日期：2026-09-06
- 决策者：项目所有者
- 关联模块：全部模块、开发工具与验证流程
- 取代：ADR-0015、ADR-0030

## 背景

ADR-0015 删除了项目测试套件，并同时禁止测试专用脚本。整盘 Backup/Restore 等高风险人工验收需要
可重复的环境准备、生产 CLI 编排、状态观察和结果记录；禁止所有脚本会迫使操作者手工拼接命令，增加
身份关联错误和结果不可审计的风险。项目所有者决定删除“禁止 test-only 脚本”的规则，同时继续禁止
测试源码、fixture、测试可执行 Target、CTest 和 CMake 测试注册。

## 决策

1. `tools/` 可以包含独立的测试、诊断和人工验收脚本。
2. 脚本默认不接入 CMake、CTest 或生产安装包；若需要接入 CI 或无人值守调度，必须单独审查权限、
   环境隔离、凭据和破坏性影响。
3. 仓库继续禁止测试源码、fixture、golden data、测试可执行 Target、CTest 用例和 CMake 测试注册。
4. 生产变更的最低验证门禁仍是 Release 生产 Target 构建、静态/架构/源码规模检查和按风险执行的运行
   或 UI 验证。脚本结果可以作为运行验证证据，但不能代替生产构建与静态检查。
5. 破坏性脚本必须默认失败关闭，要求显式确认并在动作前复检精确目标身份；不得记录凭据、SecretRef、
   token、密钥或用户文件内容。
6. `tools/AegraDiskBackupRestoreValidation.ps1` 保留 ADR-0030 建立的双重 `disk.N` 确认、系统盘拒绝、
   Schedule 源盘拒绝、Service preflight 和默认 `ConfirmDestructiveRestore = $false` 门禁。
7. 本 ADR 同时取代早期 ADR、开发计划和迁移文档中所有“禁止测试脚本”条款；这些文字仅作为历史记录，
   不再构成活动规则。

## 备选方案

- 继续禁止全部测试脚本：拒绝，会降低高风险人工验收的可重复性和可审计性。
- 恢复完整编译测试套件：拒绝，本决策只开放独立脚本，不恢复测试 Target 或 CTest。
- 默认把脚本接入 CI：拒绝，不同脚本的权限和破坏性风险差异很大，必须逐项审查。

## 影响

- ADR-0015 与 ADR-0030 被本 ADR 取代；历史文本保留用于追溯决策变化。
- 后续可以在 `tools/` 添加有明确用途、输入校验和结果输出的测试或验证脚本，无需为每个脚本建立政策
  例外 ADR。
- 代码评审仍需阻止脚本绕过生产协议、安全确认、凭据边界或模块化生产实现。

## 验证

- 活动仓库规则不再包含“禁止 test-only 脚本”或“禁止测试专用脚本”。
- `tools/` 脚本未注册为 CMake Target 或 CTest 用例。
- 破坏性脚本默认配置不会提交不可逆操作。
- Release 生产构建和静态检查流程不依赖这些脚本。
